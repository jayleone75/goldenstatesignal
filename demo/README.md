# Golden State Signal — live demo

Static site, no server, no build step. Matches the design tokens on
goldenstatesignal.com (Fraunces + Inter, navy/cream/gold palette) so it reads
as one product with the marketing site, not a bolted-on tool.

## What's in here

- `index.html` — search, filters, category spend, supplier concentration,
  confirmed-renewal signals, and "what they say they run" (job-posting
  evidence), for two live departments (DMV and CDT).
- `sample-brief.html` — one real, generated account-strategy document.
  Contacts are shown by **role only** (no names, no emails) — see the note
  below before regenerating this.
- `data/dmv.json`, `data/cdt.json` — the entire dataset the page filters.
  No contacts, no buyer names/emails, no line-item PII. Regenerated by
  `pipeline/make_demo_data.py` in the main project.
- `assets/` — CSS and vanilla JS, no framework, no dependencies.

## Deploying

The live site is served from GitHub Pages (`Server: GitHub.com` in its
response headers). To publish the demo:

1. Copy this entire `demo/` folder into the **root of the goldenstatesignal.com
   repo** as a subdirectory, e.g. `goldenstatesignal.com/demo/`.
2. Commit and push. GitHub Pages serves it at `goldenstatesignal.com/demo/`
   automatically — no config needed for a plain static subfolder.
3. Add a nav link on the homepage pointing at `/demo/` (the demo pages already
   link back to `/` for "Request a Briefing", so cross-navigation works both
   ways once this lands).

No environment variables, no API keys, no database. It's flat files.

## Refreshing the data

From the main project (`ca-procurement-intel/`):

```bash
python pipeline/make_demo_data.py
```

Re-run this any time the underlying purchase data changes, then re-copy
`demo/data/*.json` into the deployed copy. Consider a small GitHub Action that
runs this on a schedule and commits the refreshed JSON, so the demo doesn't
silently go stale — not built yet, worth adding once this is live.

## If you regenerate `sample-brief.html`

The source strategy document lives in the main project's
`output/briefs/strategy-department-of-motor-vehicles-*.md` (git-ignored — it's
generated, not source). **Do not copy a fresh one over `sample-brief.html`
directly.** Every generated brief names real buyers of record with direct
work email addresses — appropriate for a paying customer, not for an
unauthenticated public page.

Before publishing a new sample:
1. Confirm the "Who to talk to" section has no names or emails — roles only.
2. Search the full document text for every name that appeared in the
   original "Who to talk to" section — they sometimes reappear in the
   Action Items table (this happened on the first draft and was caught only
   by an explicit text search, not by re-reading the redacted section).
3. Check rendered links don't swallow trailing punctuation
   (`href="...jcid=254014)."` was a real bug in the shared Markdown-to-HTML
   converter, `pipeline/exports.py::_md_to_html`, fixed 2026-08-07 — should
   not recur, but verify on any future regeneration).

## Local preview

```bash
python -m http.server 8090 --directory demo
```

`fetch()` needs `http://`, not `file://` — opening `index.html` directly in a
browser will fail silently on the JSON load. A launch config for this is
already in `.claude/launch.json` under the name `demo-static`.
